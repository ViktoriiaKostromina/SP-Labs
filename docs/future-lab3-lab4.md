# Підготовка дослідження ЛР3–4

Це план, не виміряна baseline. Сесійний автомат і FreeRTOS зараз не реалізуються.

## Задачі майбутнього super loop
| Задача | Запуск | Deadline / валідність |
|---|---|---|
| Кнопки | 5 мс, debounce 25 мс | ≤100 мс від фізичного фронту до реакції, CLOSE перед PAUSE |
| ADC / вибір роботи | 10 мс, середнє 8 | свіжість ≤150 мс, не відкривати сесію під час прогрівання |
| RFID | 50 мс, SPI mode0 | ≤200 мс пред’явлення→подія, 3 NO_CARD для зняття |
| UART RX / команди | кожний оберт, прийом IT у кільце | ≤200 мс LF→початок відповіді, рахувати overflow |
| Журнал SD | подія переходу | ≤500 мс commit+read-back, fault не підтверджує запис |
| Повторна ініціалізація | 1000 мс у fault | відновлення ≤1500 мс після повернення |
| Статистика | 1000 мс | MCU clock; не використовувати host arrival time |

FR-05 час береться в точці прийняття події, не після блокувального UART/SD. Для ЛР3 достатній прямий super loop з перериванням RX, без власної ОС. Блокувальні операції SD/експорту треба виміряти до будь-якого поділу на кроки.

## Формат сховища
Окремий образ 8 MiB; не монтувати користувацьку картку. LBA128–511 (384 сектори) зарезервовано під журнал. У ЛР2 тільки сектор127 для bring-up: write/read/CRC/reset та зміна образу хостом. Двійковий запис v1: magic STK1, seq u32 LE, type u8, uid_len u8, uid[7], job u8, state u8, active_ms u64 LE, pause_ms u64 LE, CRC32 IEEE для визначеної довжини; решта FF. Коміт після повного read-back. В ЛР3 реалізувати скан хвоста, torn-write та INTERRUPTED; CRC не гарантує атомарність SD-FTL при реальному зникненні живлення, її досліджують на фізичній картці окремо.

## Відтворювані майбутні сценарії
- S1: 60 с MCU без картки, ручка в центрі, кнопки вільні; тисячі запусків ADC/кнопок. Старт/перезапуск окремо ≥30 повторів.
- S2: 3600 с MCU неперервно; кожні 120 с відкрити сесію карткою A, через 30 с pause, через 20 с resume, через 10 с close; зняття ≥200 мс. Команда status кожні 10 с. Перевірити всі seq/CRC, суми й відсутність пропущених інтервалів. Автоколектор перевіряє монотонний MCU час, gap, reset/banner, error counters; після початкової перевірки ≤10 хв поставити одне пробудження на залишок. Не складати перервані пробіги.
- S3: 120 с MCU; export 32 записів паралельно з реальним SD-записом, 20 команд/с, 40 натискань зі збереженим seed стимулів, 30 пред’явлень. Для кожної реакції мати стимул і GPIO, не лише UART-текст. Не підміняти SD-запис HAL_Delay.
- §6.2: довга SD-операція+ADC; ≥30 кнопок під час неї; UART flood з лічильником RX loss; RFID disconnect/return; SD busy timeout; ступені 1/5/10/20/40/80 команд/с до порушення; delayed readiness; reset усередині CMD24 і CRC-хвіст. Зберігати невдалі прогони.

## Методика
Cortex-M0+ не має DWT CYCCNT. Використати доступний апаратний таймер (TIM3, перевірити режим моделі) як 1 МГц із розширенням переповнення, або явно обмежений SysTick+VAL; тривалі інтервали — розширений HAL tick. Службові GPIO: вхід задачі, вихід, подія й реакція. Порівняти хоча б один інтервал з VCD незалежно. Зберігати метод, роздільність/похибку, hashes ELF/HEX, схему, вхідні стимули, raw UART/VCD. Для задач min/avg/max/p99, jitter, releases/missed; подій ≥30, періодичних запусків тисячі. CPU useful work відокремити від idle/spin і накладних витрат вимірювання. Пам’ять: map/size/nm, -fstack-usage, фактичне stack painting, heap і резерв.

## Перед ЛР4
Зберегти збираний lab3; не змінювати FR, UART та парсери. Обидві версії повторити в один день на тому самому стенді, 48 МГц/115200/ті самі стимули й інструменти. Порт FreeRTOS потрібен для ARM_CM0 (без FPU), а не ARM_CM4F із прикладу методички. Розміри стеків і RAM вибирати за вимірюваннями. Повторити шість §7.2: mutex/семафор інверсія, stack overflow on/off, starvation, queue exhaustion, heap exhaustion, 1000/100 Гц tick. Виміряти tick/context switch/ISR→task/kernel flash+RAM, stack/heap кожної задачі. Перевірити кожну гіпотезу ЛР3, включно з перевагами super loop. Негативний результат допустимий; FreeRTOS не зобов’язана виграти всі метрики.
